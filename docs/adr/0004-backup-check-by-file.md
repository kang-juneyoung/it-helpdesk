# ADR 0004. 백업 점검은 "최신 파일의 시각과 크기"로 판단한다

- 상태: 채택
- 날짜: 2026-10-19

## 배경

백업 프로그램이 "성공"이라고 기록해도 실제 파일이 비어 있거나, 예약 작업이 멈춰 며칠째 새 파일이
없는 경우가 있다. 백업은 필요할 때 처음 확인하면 늦다.

## 결정

- `bin/check_backup.php`를 cron으로 매일 실행한다. `BACKUP_DIR` 아래 폴더 하나가 백업 대상 하나다.
- 대상 폴더마다 가장 최근 파일을 찾아
  - 파일이 없으면 실패
  - 크기가 0이면 실패
  - 마지막 수정 시각이 `BACKUP_MAX_HOURS`(기본 26시간)보다 오래되면 실패
  - 그 외는 성공
- 결과는 백업 점검 일지에 "자동"으로 기록하고, 실패가 하나라도 있으면 종료 코드 1을 돌려준다.
  cron 메일이나 모니터링 도구가 종료 코드로 알림을 보낼 수 있다.
- 복구 테스트처럼 사람이 확인하는 일은 화면에서 "수동"으로 기록한다.
- 대시보드 경보는 대상별 최신 기록을 **점검 시각 기준**으로 고른다.
  (처음에는 입력 순서로 골라, 과거 날짜로 나중에 입력한 수동 기록이 최신으로 잡히는 버그가 있었다.
  고친 뒤 이 경우를 테스트로 고정했다.)

## 결과

- 좋은 점: 백업 프로그램 종류와 상관없이 같은 방식으로 점검된다.
- 한계: 파일이 있어도 내용이 깨졌는지는 모른다. 그래서 월 1회 복구 테스트를 수동으로 기록하는 절차를 함께 둔다.
